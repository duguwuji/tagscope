# TagScope 2026-11-05 变更记录

日期：2026-11-05。本轮完成上一轮分析中剩余的三项：前端规模化性能、REST 能力标注、CI 与版本号单一来源。版本号仍为 2.0.1；实机验收由项目维护者完成。

## 1. 盘点展示的增量渲染与内存上限

| 项目 | 行为 | 主要位置 |
|---|---|---|
| 增量行更新 | 列表视图按 EPC 缓存 `<tr>`，每帧只更新变化的单元格；不再每 250 ms 重建整个 `tbody` 的 HTML。列变化时才重建表头与行。 | public/views.js |
| 行重排节流 | 默认按 `#` 升序时只追加新行；其他排序列最多每 750 ms 重排一次，用户点击排序时立即重排。 | public/views.js |
| 排序节流 | `since`、读取次数等易变列最多每秒重新排序一次；`#` 升序直接复用插入顺序数组。CSV 导出仍强制使用当前排序。 | public/views.js |
| 时间着色 | 行背景按 24 级量化，只在色阶变化时写入 `style`。 | public/views.js |
| 唯一标签上限 | 内存中最多保留 200,000 个唯一 EPC；超过后新 EPC 不再计入，已有标签继续更新。页脚、日志页和 CSV 头会显示上限与未计入的读取次数。 | public/views.js |
| TID 检测缓存 | 不再每帧遍历全部标签判断是否显示 TID 列，改为在收到 TID 时置位。 | public/views.js |

列表视图仍最多显示 3,000 行；导出 CSV 不受该显示上限影响。

## 2. REST 驱动明确标注为“仅盘点”

| 项目 | 行为 | 主要位置 |
|---|---|---|
| 能力字段 | REST 驱动信息增加 `supportsGpi: false`、`supportsBlockWrite: false` 和 `accessNote`，与已有的 `supportsAccess: false` 一起下发到页面。 | lib/driver-rest.js |
| 服务端拒绝 | `/api/access` 对不支持标签操作的驱动返回明确的“仅支持盘点，请改用 LLRP”错误。 | server.js |
| 界面提示 | 标签存储页只列出支持标签操作的数据源；没有可用数据源时显示 REST 限制说明；从 REST 标签打开存储页时状态栏给出提示。设备信息中新增“标签操作 / GPI 触发”能力行。 | public/views.js、public/app.js、public/index.html |
| 文档 | 中英文 README 增加驱动能力矩阵，并更新 REST 注意事项。 | README.md、README.en.md |

未实现 REST 标签操作的原因：Impinj IoT Device Interface 的标签访问接口没有可离线核验的公开契约，盲实现可能向真实读写器发送错误请求。当前选择是明确拒绝并引导使用 LLRP，而不是提供未经验证的功能。

## 3. CI 与版本号单一来源

| 项目 | 行为 | 主要位置 |
|---|---|---|
| 语法检查 | `npm run check` 检查 `server.js`、`lib/`、`public/`、`test/`、`scripts/`，并以 ES module 方式检查 `worker.js`。 | scripts/check-syntax.js |
| 测试入口 | `npm test` = `npm run check` + 回归测试 + 模拟 LLRP 端到端测试。 | package.json |
| GitHub Actions | push 到 `main` 和所有 Pull Request 上，用 Node 18/20/22 运行 `npm test`。 | .github/workflows/ci.yml |
| 版本注入 | `package.json` 是唯一版本来源；`server.js` 与 `worker.js` 注入 `<meta name="tagscope-version">`，前端从该 meta 读取。HTML 脚本标签不再带版本查询参数。 | package.json、server.js、worker.js、public/index.html、public/app.js |
| Worker 缓存 | Worker 继续按脚本内容哈希生成 `?v=`，与版本号解耦。 | worker.js |
| 回归覆盖 | 新增版本注入、REST 仅盘点、唯一标签上限三项测试。 | test/regression.test.js |
