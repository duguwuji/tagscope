# TagScope 2026-11-04 修复记录

日期：2026-11-04（北京时间）。本轮针对上一轮审核中确认的安全、正确性和可维护性问题执行修复；版本号仍为 2.0.1，部署前仍需实机与浏览器验收。

## 安全与部署

| 项目 | 修复与可观察行为 | 主要位置 |
|---|---|---|
| 密钥与本地数据 | `.gitignore` 增加 `data/`、`*.key`、`*.pem`、`*.crt`、`.env`、`.wrangler/`，避免 TLS 私钥和本地配置被误提交。 | .gitignore |
| 页面 CSP | 本地桥接为每个 HTML 响应生成随机 nonce，只有注入的配对码脚本和同源脚本可执行；Worker 使用内联云标记的 SHA-256 哈希。回归测试会从页面提取内联脚本并重新计算哈希，防止哈希与脚本漂移。 | server.js、worker.js、test/regression.test.js |
| GPO 输出转义 | GPO 端口在写入 `data-port` 和提示文本前统一转义，避免异常端口值破坏 HTML 属性。 | public/views.js |
| 静态文件错误 | 静态脚本改为流式读取；文件不存在或读取失败返回 404，不再产生未处理的流错误；客户端断开时销毁流。 | server.js |
| 退出清理 | SIGINT/SIGTERM 先停止盘点并断开所有数据源，再退出进程，降低读写器仍在盘点的风险。 | server.js |
| TLS 校验 | LLRP 数据源回退到 Impinj IoT 接口时，传递数据源的自签名证书选项；取消“允许自签名证书”后不再无条件跳过证书校验。 | server.js、lib/driver-rest.js |
| Windows 启动 | 启动脚本延迟 2 秒再打开浏览器，避免桥接尚未监听时出现连接失败。 | start-windows.bat |

## 前端正确性

| 项目 | 修复与可观察行为 | 主要位置 |
|---|---|---|
| 配对取消 | 取消配对后 30 秒内不再连续弹窗，30 秒后允许重新提示；配对成功后清除冷却时间。 | public/app.js |
| SSE 数据缺口 | `INCOMPLETE_DATA` 不再被当作普通网络错误吞掉，而是进入数据错误处理：标记当前运行不完整、写日志并提示；其他异常仍输出到控制台。 | public/app.js、public/views.js |
| 接收端缺口恢复 | 标签批次出现不可恢复缺口时只报错一次并停止缓存，不再让接收端永久处于中毒状态；下一次运行可重新开始。 | public/run-buffer.js |
| 停止卡死 | 停止时桥接端 `runId` 已改变会清除本地卡住的运行状态并提示重新开始；多数据源中“运行已改变”与“数据不完整”混合时，仍能识别为运行已改变。 | public/views.js |
| 凭据存储 | 读写器用户名/密码改存 `sessionStorage`，关闭浏览器后需重新填写；启动时把旧 `localStorage` 中的明文凭据迁移到会话存储，并在保存成功后删除旧的 v1 `tagscope.source` 记录。 | public/app.js、docs/user-guide-zh.md、docs/user-guide-en.md |
| 渲染与内存 | i18n 跳过仅含数据的 `[data-epc]` 盘点行；趋势图点数限制为约 2 万；TOI 保存失败会提示；8 位颜色值按 6 位处理。 | public/i18n.js、public/views.js |
| 表单结构 | 修复“使用 TLS / 允许自签名证书”的嵌套 `<label>`，避免点击标签时触发错误控件。 | public/index.html |

## 驱动与模拟器

| 项目 | 修复与可观察行为 | 主要位置 |
|---|---|---|
| REST 过滤器 | 按 Gen2 语义把 `match`/`miss` 的合法组合映射为 REST 的 `include`/`exclude`，包括 `match=nothing` 时由 `miss` 决定动作的情况；无有效掩码时不发送过滤器。 | lib/driver-rest.js |
| REST RF 模式 | 为 R700/R660 IoT 接口提供其接受的 RF 模式列表（0–4、1000、1002、1003、1004），避免界面使用仅 LLRP 支持的模式编号。 | lib/driver-rest.js |
| 模拟器永久解锁 | `permaunlock` 不再被模拟器当作受保护状态，写入可按永久解锁语义执行；`lock` 仍会阻止无正确密码的写入。 | public/sim.js |

## 验证

- `npm test`：37 项回归测试全部通过，0 失败；包含内存 LLRP 端到端流程。
- 全部 JavaScript 文件通过 `node --check`；Worker 按 ES module 检查。
- 新增回归覆盖：接收端不可恢复缺口、REST 过滤器全部合法动作组合、模拟器 `permaunlock`、Node CSP nonce 与脚本一致、Worker CSP 哈希与内联脚本一致、停止时混合错误分类、旧凭据迁移与 v1 记录删除。
- 未连接真实读写器或标签；未做浏览器端到端操作；Worker 测试验证静态路由与文本资产，不等于 Wrangler 构建或线上部署验收。

## 仍需实机或后续处理

- 盘点表目前仍按约 250 ms 的节奏整体重绘；大数据量下可改为增量更新行。
- `tags` 与 `srcStats.epcs` 仍随唯一 EPC 数量增长，长时间大规模盘点需要上限或分页策略。
- 部分回归测试依赖源码切片，重构前端函数时容易失效，后续可改为导出可测试的纯函数。
- 低占空比（LDC）编码和 REST `rfMode` 的实际读写器行为需在目标固件上验证。
- `wrangler.toml` 的 `[previews]` 配置需在 Cloudflare 构建中确认；本环境未执行 Wrangler 部署。
- `data/tls/reader.key` 已被忽略；若该文件曾经分发或提交到其他位置，应轮换证书。
